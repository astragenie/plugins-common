## Lessons

- AC-3 staleness is a DOMAIN outcome, not an error — the reader warns (`stale_registry`) and still resolves `found:true`; a stale entry that stopped resolving would be a different, equally-wrong failure. The builder correctly kept resolveName throw-free (not-found/stale/uncomparable all Result-shaped) per DEC-002, and the tests assert the stale entry STILL resolves, which is the subtle correctness point.
- Version comparison is exactly the place NOT to hand-roll: builder added the `semver` package (vs the deliberate no-ajv hand-roll for schema) because prerelease/build-metadata parsing is error-prone — right call, different from the SLICE-1 validator decision.
- product_completeness scored 0.78 (not higher) because the slice met the FEAT's AC-3 but under-delivered vs the ADR's broader reader description (multi-producer merge + cross-plugin collision detection) with no descope note in the plan — see Followups.
