## Lessons

- A builder PASS claim ("typecheck exit 0") is not evidence — live LSP diagnostics showed 8 type errors in file-lock-manager.ts. Re-running the actual command showed exit 0 (diagnostics were a stale mid-edit snapshot). Lesson: verify with a fresh command run; treat both the builder claim AND the IDE diagnostic as untrusted until reproduced.
- The "inconsistency" framed by FEAT-008 hid a real design tension between two accepted decisions (DEC-001 never-throws-acquire vs result.ts throw-for-infra). Resolved by recognizing lock contention is a domain outcome (ok(null)), not infra — so throw-for-infra and never-throws-on-contention are not in conflict. Not a mechanical sweep.

## Surprises

- Reviewer surfaced a MEDIUM (out-of-scope but real): tryAtomicWrite throws `TransientError` for every non-EEXIST fs errno (EACCES/ENOSPC/EROFS/ENOTDIR), lumping deterministic failures into the retry-safe class — same shape as the SLICE-05 maxBuffer lesson. jsonl.ts/http.ts/git.ts already do this, so it's a pre-existing cross-cutting classification gap, not a regression from this slice.

## Followups

- File an errno-classification audit FEAT: map fs/network error codes to transient-vs-deterministic across file-lock-manager.ts, jsonl.ts, http.ts, git.ts before cross-repo adoption relies on the retry semantics.
