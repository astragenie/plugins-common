## Lessons

- The adversarial correctness reviewer paid for itself: it reproduced a live path-traversal exploit (`--plugin ../../evil` wrote agents.json OUTSIDE outputDir + stamped the raw traversal string as `sourcePlugin`) that the builder's 38 green tests + the TS-idiom reviewer both missed. Green tests prove the happy path; only an adversarial "try to break the security boundary" pass finds the injection. For any slice that builds a value-flows-to-filesystem/CI boundary, a dedicated security review is non-optional.
- Sanitize EVERY externally-controlled value that reaches a path or a published manifest, not just the obvious one. The builder validated frontmatter `name` (AC-5) but missed `opts.plugin` (the CLI arg used for BOTH path construction and `sourcePlugin` stamping) and `version`. One unguarded input undid the whole allow-list.
- Stale IDE diagnostics fired 3× this slice (missing node/bun libs, unused renameSync) contradicting a clean `tsc --noEmit`; each was a mid-edit LSP snapshot, not a real error. Re-running the actual command is the only trustworthy signal.

## Surprises

- The allow-list regression risk was the opposite of expected: the worry was it would reject legit namespaced names (`crew:reviewer`, `@scope/x`), but real crew/dev-team frontmatter `name` fields are plain lowercase-hyphenated slugs — the `crew:reviewer` form is Claude Code dispatch namespacing assembled outside this generator, never a literal manifest value. Allow-list is safe.

## Followups

- Cross-repo COMPANION FEATs (cannot be built from plugins-common — file in the owning repos): (a) crew/dev-team release-CI generates + PRs its manifest into plugins-common; (b) runner-plugin `validate-agent-refs.mts` reads the published registry instead of its frozen local allowlist Set. Both are the actual FEAT-240-class fix; SLICE-1 only built the plugins-common-side generator they depend on.
- Residual disclosed non-blocking: two-rename window (agents.json renames, then skills.json rename fails) can leave a single-file partial publish — would need a manifest-level transaction to fully close; out of scope per review.

## Decisions

No new DEC minted at grade time.

## What went well

Clean new package mirroring gepa-core conventions; reused plugin-std frontmatter + errors + DEC-002 throw policy; hand-rolled JSON-Schema validator avoided an ajv runtime dep; schema ships inside the npm artifact so producer repos can consume without plugins-common checked out. Security fix added 10 targeted regression tests (48 total) and made the writes atomic (temp+rename).

## What went wrong

Builder shipped a security hole (unvalidated `opts.plugin`) behind a green suite, forcing a full REJECT→fix→re-review cycle — the single biggest time cost of the slice. The happy-path test design didn't include any hostile-input case for the CLI arg.

## What I would do differently next time

Require builders of any filesystem/manifest-writing surface to include hostile-input tests (path traversal, control chars, absolute paths) in their FIRST pass, so the security boundary is proven at build time rather than discovered at review time.
