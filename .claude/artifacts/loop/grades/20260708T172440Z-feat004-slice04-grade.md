## Lessons

- Pure-extraction slices (no in-repo consumer) still get full value from a hard test matrix: the CRLF/LF/BOM deep-equality matrix + round-trip fidelity tests are what make a frozen API safe for the cross-repo consumers that WILL adopt it, standing in for a first-consumer proof this repo can't provide.
- `parseFrontmatter<T>` casts unvalidated YAML straight to the caller's generic — acceptable ONLY because the module's documented scope is "no domain validation, caller owns it". If a future consumer wants validated parsing, that's a separate zod-boundary helper, not a change to this core.
- First new third-party runtime dep of the milestone (`yaml@^2.6.0`) — no YAML parser existed in the workspace to reuse. Single-entry, no transitive bloat, resolved 2.9.0.

## Surprises

- An unindented literal `---` inside a raw YAML block scalar would false-positive as the closing fence — inherent to line-oriented fence parsing, shared by the runner seed being replaced. Not a regression; documented limitation.
